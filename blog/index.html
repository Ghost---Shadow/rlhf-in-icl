Appeasing the Machine Spirit

Souradeep Nanda · November 2026

Read the preprint (PDF) Two rites for predicting, and then preventing, a solo developer's playtest notes.

I'm making a game alone: The Good Vet, an open-world vet game with soulslike fights. Every few days I play the latest build and write down everything that bothers me. Then the list goes back into the todo, the todo gets built, and I play again.

After a month there were sixteen of those lists in git, each one written against a todo. That's a dataset. So I asked an agent two questions. Can you read the todo and predict what I'll write? And if you can, can you change the todo so I don't have to write it?

Two rites

Nothing is fine-tuned. The "weights" are one markdown file in the agent's memory folder. The "dataset" is git tags pairing each todo with its list. Each epoch is a fresh agent, cleansed of all prior context. That's the zero_grad(), so the file is the only thing that carries over.

The First Rite trains the memory. An agent reads the memory, forecasts each past list from its todo, opens the real list, writes down what it got wrong, and rewrites the memory.

The Second Rite freezes the memory and changes the todo instead. It forecasts what I'll complain about once the todo is built, writes those complaints into the todo as fixes, and forecasts again, until nothing new comes up. It's like optimising the input against a frozen network.

If both rites work, my next playtest list comes back empty, and the machine spirit is appeased.

The First Rite: train the memory on past (todo, list) pairs
  for each epoch:
    agent = fresh agent                      # zero_grad()
    for each past pair, in order:
      forecast = agent.predict(memory, todo, earlier lists)   # before the list is opened
      loss     = agent.compare(forecast, real list)          # a count, and what went wrong
    memory = agent.rewrite(memory, patterns in the losses)  # do/don't rules, no past notes
    commit memory                            # checkpoint
    stop when held-out hits stop rising

The Second Rite: freeze the memory, converge the todo
  repeat:
    agent    = fresh agent
    forecast = agent.predict(memory, todo, every past list) # as if the todo were built
    new      = lines the todo doesn't cover yet              # the loss
    todo     = fold(todo, new)               # boxes, watch lines, decisions
    commit todo
  until new is (almost) empty

The curve that lied

Training accuracy went from 5.5% of my notes to 21% in four epochs, which looked great. Then the scorer pointed out that many hits repeated my notes almost word for word. Each epoch, the agent had written my past notes into the memory: offender lists, per-tool wish lists. By epoch four, about 81 of its 119 hits were recall. With that removed, the curve was flat from epoch two.

"This is cheating. You can't just write out the diff in the memory itself."

So we held out my last three lists and trained a fresh memory on the rest. On the lists it had never seen, it caught 4, 5 and 6 notes out of 191: about 3%. An agent with no rules memory at all, reading my earlier lists raw, caught 29. Five times better.

What actually predicts me

Most of my notes are repeats of named things, half-finished asks, or the next step of a wish I already made. Those live in the raw history, not in rules about the history. A rule like "fixes checked only by a test come back" is true, but it doesn't say which thing will come back.

So the memory was rewritten as general do/don't pairs, each rule with its opposite, with none of my past notes in it. Frozen and tested, it caught 5.7% with zero recall, and twice the held-out score of the trained rules. Most of its misses were rules it already had but no room to write, because I'd capped it at twelve lines. A predicted problem I don't mention costs nothing. It could be an oversight on my part.

Turning the forecast into work

The Second Rite took the frozen memory, today's todo and all sixteen lists, and forecast 176 notes for my next playtest. Twenty-two turned out to be already handled in the code. The rest became 64 fix boxes, 35 warnings on existing boxes, and 9 decisions with defaults. Every box says how it gets checked without me playing.

Then the rite ran again on the new todo, with a fresh agent each round. Each round found about half as much as the one before: 176 new issues, then 79, then 44. Most of each round's finds were faults in the last round's fixes, which is what you'd expect: every fix adds a little surface.

The real test is my next playtest. If the list is short, the spirit is appeased. If it isn't, the list becomes pair seventeen, and the First Rite begins again.

What I'd tell you

Measure recall, or your curve will lie. Keep the labels out of the weights. Give the model the raw history, and spend the memory on how to read it. And a fresh agent per epoch is expensive, because onboarding is costly, just like real life.
